Session B เริ่มจากศูนย์จริง ๆ. ถ้าจะให้มันทำงานต่อได้ ต้องส่งอะไรข้ามไป?
  • (ก) บทสนทนาทั้งหมดของ Session A?

เบาะแส: (ก) ใหญ่เกินและกินโควตาซ้ำ · (ข) Session B เปิดเองได้อยู่แล้ว แต่มันไม่รู้ว่าต้องเปิดอันไหน และเปิดไปทำไม
📄 ในไฟล์มีอะไร — และตั้งใจ “ไม่มี” อะไร
  • มี — สิ่งที่มีอยู่แค่ในหัวบทสนทนา: ทำอะไรค้างไว้, ตัดสินใจอะไรไปแล้วเพราะอะไร, อะไรคือ step ถัดไป, ทางไหนลองแล้วไม่เวิร์ก
  • มี — ส่วน suggested skills: บอก agent ใหม่ตรง ๆ ว่าควรเรียก skill ไหนต่อ
  • ไม่มี — เนื้อหาที่ artifact อื่นเก็บไว้อยู่แล้ว (spec, plan, ADR, issue, commit, diff) → เขียนเป็น พาธหรือ URL แทน
  • ไม่มี — API key, password, PII → ถูก redact ออก
⚠️ ทางที่ดูสมเหตุสมผลแต่พัง — “ยัดทุกอย่างลงไฟล์”
ถ้าเขียน handoff แบบ copy เนื้อ ADR/spec/diff ลงไปทั้งดุ้น:
  • มันค้าง — พรุ่งนี้ ADR ถูกแก้ ไฟล์ handoff ยังเล่าเวอร์ชันเก่า และ Session B เชื่อไฟล์ที่ผิด
  • มันโต — ไฟล์ 40 KB กินโควตา Session B ทันทีที่เปิด ซึ่งคือปัญหาที่เราหนีมาตั้งแต่แรก
  • มันซ้ำ — ความจริงมีสองที่ แล้วไม่มีใครรู้ว่าที่ไหนถูก
นี่คือเหตุผลที่กติกา “อ้างถึง ไม่ใช่คัดลอก” ไม่ใช่แค่เรื่องประหยัดที่ — มันคือเรื่องความถูกต้อง
⌨️ ต้องพิมพ์อะไรจริง ๆ — 2 จุด และทั้งสองจุดคุณต้องทำเอง
  • ตอนจบ Session A → /handoff ทำ VIN e2e ต่อ J-32 ถึง J-40
    ข้อความหลังคำสั่งคือ “ทิศ” ของ session หน้า — agent จะเขียนไฟล์โดยเอียงไปทางนั้น แล้วตอบพาธไฟล์กลับมา
  • ตอนเปิด Session B → อ่าน %TEMP%\handoff-vin-e2e.md แล้วทำงานต่อ
    ไม่มีอะไร auto — ถ้าไม่วางพาธ Session B ก็ยังเป็นกล่องสีแดงเหมือนเดิม
ข้อแลกที่ต้องรู้: ไฟล์อยู่ใน temp → ไม่เข้า git, ไม่มี history, โดนลบได้เมื่อล้าง temp (ถ้าอยากเก็บถาวร ย้ายเข้ารีโปเอง) · พอยน์เตอร์พังได้ถ้า path ถูกย้าย/rebase · และคุณภาพ handoff = คุณภาพที่ Session A เข้าใจงาน — ถ้า A เข้าใจผิด ความเข้าใจผิดจะถูกส่งต่อแบบมั่นใจมาก
